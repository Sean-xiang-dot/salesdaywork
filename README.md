# 销售动作采集与主管督导台

这是一个面向城市内部销售管理的过程督导工具。它的目标不是简单把日报搬到线上，而是把销售顾问每天分散的工作过程前置沉淀下来，让日报可以基于过程数据自动汇总，同时为主管提供更直观的团队分析和过程管理视图。

## 腾讯云发布

腾讯云版本采用固定的版本化发布流程。应用代码位于 `/opt/salesdaywork/releases`，当前生效版本由 `/opt/salesdaywork/current` 指向，业务数据独立保存在 `/var/lib/salesdaywork`，发布新版本不会覆盖已有日报、商机和拜访数据。

日常发布步骤：

```bash
git push origin main
npm run deploy:tencent
```

发布命令会从 GitHub 下载最新 `main`，执行语法检查，切换版本，重启服务并调用 `/api/health` 验证。若启动或健康检查失败，会自动恢复到上一个版本。服务器默认保留最近 5 个发布版本。

服务器运维命令：

```bash
sudo systemctl status salesdaywork
sudo journalctl -u salesdaywork -n 100 --no-pager
sudo /opt/salesdaywork/deploy.sh
```

需要发布其他分支或提交时，可以在服务器指定 `RELEASE_REF`：

```bash
sudo RELEASE_REF=<branch-or-commit> /opt/salesdaywork/deploy.sh
```

### CRM 集成配置

腾讯云 Node 版已接入销售易 OAuth 登录和 CRM 数据接口。当前口径如下：

- 登录：通过销售易 OAuth 授权，系统只保存当前会话、CRM 用户 ID、姓名、邮箱、部门字段和 access token。
- 角色：优先读取 CRM 用户角色/岗位/职务字段，包含 `组长`、`负责人`、`分公司负责人`、`主管`、`经理`、`总监`、`城市经理`、`区域负责人` 等关键词时识别为主管；`CRM_MANAGER_NAMES` / `CRM_MANAGER_EMAILS` 仅作为兜底配置。
- 团队范围：主管登录后会优先按当前 CRM 用户的 `dimDepart` 查询同部门用户，作为看板和提交人下拉的可见顾问范围；顾问只看自己。
- 数据权限：`/api/state` 已按角色裁剪。顾问读取和保存都只处理自己的日报、商机、拜访、线上记录、AI 评分和同步日志，不会覆盖其他顾问数据。
- 客户缓存：`/api/crm/accounts` 会从 CRM 查询当前登录人名下客户并缓存在服务器，拜访和商机客户字段可用本系统做模糊搜索。
- 业绩取数：`/api/crm/performance` 查询 `SalesPerformance__c`，按 `NewOrOldSP__c` / `new_or_addon__c` / `newType__c` 区分；新客和增购计入新签，老客计入老客。
- 拜访同步：`/api/crm/visits` 将已匹配 CRM 客户的拜访记录创建为 CRM `activityrecord`，并自动补充 `ownerId`、`dimDepart`、`entityType` 等字段。
- 商机与日报动作同步：`/api/crm/actions` 采用手动同步和失败重试机制，先将商机推进、日报客户动作写入 CRM `activityrecord` 作为过程留痕。
- 商机主表同步：`/api/crm/opportunities` 已预留可配置写回能力，通过 `XIAOSHOUYI_OPPORTUNITY_OBJECT` 和 `XIAOSHOUYI_OPPORTUNITY_FIELD_MAP` 指定销售易对象 API 名与字段映射后，可创建或更新 CRM 商机对象。
- CRM 线索承接：`/api/crm/lead-records` 按提交人从销售易线索对象拉取已分配线索并缓存在本系统，日报页只填写当天承接、沟通情况和下一步计划。
- 线索对象同步：`/api/crm/leads` 已预留可配置写回能力，通过 `XIAOSHOUYI_LEAD_OBJECT` 和 `XIAOSHOUYI_LEAD_FIELD_MAP` 指定销售易线索对象 API 名与字段映射后，可把承接结果更新回 CRM 线索对象。

常用环境变量：

```bash
CRM_MANAGER_ROLE_KEYWORDS=组长,负责人,分公司负责人,主管,经理,总监,城市经理,区域负责人
CRM_MANAGER_NAMES=张三,李四
CRM_MANAGER_EMAILS=manager@example.com
CRM_CACHE_TTL_MS=1800000
XIAOSHOUYI_VISIT_ENTITY_TYPE=3771327758883690
XIAOSHOUYI_OPPORTUNITY_OBJECT=Opportunity__c
XIAOSHOUYI_OPPORTUNITY_FIELD_MAP={"customer":"name","accountId":"accountId","ownerId":"ownerId","amount":"amount","stage":"stage","progress":"description","nextActionDate":"nextActionDate"}
XIAOSHOUYI_OPPORTUNITY_DEFAULTS={}
XIAOSHOUYI_LEAD_OBJECT=Lead__c
XIAOSHOUYI_LEAD_FIELD_MAP={"customer":"name","ownerId":"ownerId","accountId":"accountId","source":"source","stage":"status","progress":"description","nextPlan":"nextPlan","assignedAt":"createdAt","firstTouchAt":"firstTouchAt","updatedAt":"updatedAt"}
XIAOSHOUYI_LEAD_QUERY_WHERE=status != 'closed'
XIAOSHOUYI_LEAD_DEFAULTS={}
```

上面 `Opportunity__c`、`Lead__c` 和字段名只是示例，正式上线前需要按销售易实际对象 API 名和字段 API 名替换。

## 项目背景

销售团队在填写日报时，最大的困难不是不会写，而是信息过于分散。

顾问每天的客户拜访、商机推进、线上线索、成交进展等内容，往往分布在不同地方。有些在线下沟通中，有些在个人记录里，有些还需要从其他系统中导出后再整理。到了写日报的时候，还要重新回忆、重新拼凑，既费时间，也容易遗漏。

同时，拜访记录、商机进展这类过程数据，很多时候会拖到月底再集中补录到 CRM，重复劳动较多，也会影响数据的及时性和准确性。

因此，这套系统希望形成一条更顺的工作链路：

```text
平时随时记录 -> 日报自动沉淀 -> 主管实时查看 -> 后续联动 CRM
```

## 系统定位

系统主要承担三项作用：

- 承接顾问日常工作记录
- 自动汇总日报内容
- 为主管提供团队与个人的分析看板

它可以理解为 CRM 外围的轻量过程采集层：顾问先在这里低成本记录动作和进展，主管先在这里做日常复盘和督导，后续再把关键过程数据同步回 CRM。

## 整体流程

1. 顾问在日常工作过程中，随时记录拜访、商机、线上运营等过程数据。
2. 到日报提交时，只需补充当天结果类信息和次日计划。
3. 系统自动汇总已有过程数据，形成日报内容。
4. 日报提交后，联动更新商机池、拜访记录和管理看板。
5. 主管通过看板查看团队状态、商机风险和个人表现。
6. 后续如接入 CRM，可将过程数据同步过去，减少月底集中补录。

## 模块概览

| 模块 | 主要功能 | 实现效果 |
| --- | --- | --- |
| 看板模块 | 展示提交率、A级商机、漏斗金额、风险商机、团队排名 | 主管快速掌握团队整体状态 |

## 功能说明

### 看板模块

主要能力：

- 展示日报提交率
- 展示 A 级商机数量
- 展示线上转化线索数
- 展示销售漏斗金额
- 展示平均拜访评分
- 展示团队 PK 排名
- 展示高风险商机提醒
- 展示主管今日检查台

实现效果：

- 主管可以快速看到团队当天整体状态
- 不需要逐条翻日报，也能判断团队动作是否正常
- 能更快发现未提交日报、商机停滞、动作偏少等问题

### 日报提交模块

主要能力：

- 填写日期、提交人、业绩、触达情况等基础信息
- 填写额外工作和明日计划
- 自动带出本周待跟进商机
- 在日报页直接补充商机今日进展、下一步计划、下次跟进时间
- 在日报页直接填写拜访记录
- 保存日报后沉淀修改记录，便于追踪日报是否后补或调整

实现效果：

- 日报从重新整理填写，变成过程基础上的补充汇总
- 顾问填写成本明显降低
- 日报内容更完整，也更容易落到具体动作上

### 商机推进模块

主要能力：

- 维护商机的顾问、客户、来源、需求、金额、阶段、状态等信息
- 记录商机当前进展
- 记录下次跟进时间和预计成交时间
- 支持 Excel 式在线编辑
- 默认保留空白行，录入后自动补充新行
- 客户字段支持 CRM 客户搜索和预览

实现效果：

- 商机推进过程更清晰
- 重点商机更容易追踪
- 高金额商机长期停滞、下一步不清晰等问题更容易被发现

### 拜访记录模块

主要能力：

- 记录拜访日期、客户名称、拜访方式、拜访目的
- 记录沟通要点、客户痛点、下一步计划、截止日期、评分
- 支持日报填写时同步沉淀拜访记录
- 客户字段支持 CRM 客户搜索和预览
- 可将已匹配 CRM 客户的拜访记录同步为 CRM 过程记录

实现效果：

- 拜访内容可以当天记录、当天沉淀
- 避免月底集中回忆和集中补录
- 拜访质量更容易被主管看到和评价

### 线上运营模块

主要能力：

- 记录平台发布数据、浏览量、点赞、收藏、评论、私信、线索转化等内容
- 支持线上运营数据录入和后续同步扩展

当前判断：

- 小红书后台数据直接自动获取有一定难度，通常需要账号授权、后台导出或服务商接口。
- 当前版本优先支持手工录入或半自动导入，后续再根据账号和接口条件扩展。

实现效果：

- 线上动作也能纳入日报和管理视图
- 不再只看线下拜访，线上获客过程也能留痕
- 有利于更全面评估顾问的工作产出

### AI 点评模块

主要能力：

- 对日报进行自动评分
- 输出日报亮点、问题和建议
- 输出评分依据
- 自动生成周报草稿
- 支持主管点评沉淀

实现效果：

- 主管可以更快看到每个人的重点情况
- 减少人工逐条阅读日报的压力
- 帮助顾问形成更明确的改进方向

### CRM 同步模块

主要能力：

- 展示哪些内容适合后续同步到 CRM
- 支持 CRM 登录和角色识别
- 支持 CRM 客户缓存和模糊搜索
- 支持 CRM 销售绩效取数
- 支持拜访记录同步到 CRM
- 展示同步日志和失败重试队列

实现效果：

- 为后续打通 CRM 做准备
- 形成一次录入、多处复用的方向
- 减少月底集中补录的重复劳动

## 当前版本核心优势

### 随时记录，日报自动沉淀

顾问每天的工作内容可以直接在系统中记录，不需要等到下班后再统一整理。日报提交时，系统已经沉淀了大量过程数据，只需补充少量结果信息即可完成。

### 减少重复录入

拜访记录、商机推进等内容平时就可以进入系统。后续如果打通 CRM，就不需要在月底重新集中补录，能明显减少重复劳动。

### 主管视角更直观

系统把日报、商机、拜访和线上数据整合成统一看板。主管可以直接看到团队和个人的动作表现，而不是只看最终结果。

### 更容易发现过程问题

系统不仅记录结果，也能识别过程中的问题，例如：

- 商机长时间未更新
- 下一步计划不清晰
- 动作量不足
- 拜访质量偏弱
- CRM 同步失败
- 日报未提交或质量偏低

## 当前已经体现的效果

- 日报填写更轻量

## 技术说明

当前版本是一个部署在 Cloudflare Pages 上的轻量 Web 应用：

- 前端：原生 HTML/CSS/JavaScript
- Functions：Cloudflare Pages Functions
- 数据：Cloudflare KV 结构化存储
- CRM：通过现有 CRM MCP/接口能力进行登录、客户缓存、业绩取数和拜访同步
- AI：提供 `/api/ai/score` 接口，支持外部 AI 评分服务；未配置时使用后端规则评分兜底

## 结论

这套系统的核心价值，不是单纯把日报电子化，而是把销售顾问每天分散的工作过程前置沉淀下来。

它主要解决三个核心问题：

- 日报填写繁琐
- 过程数据分散
- 月底重复补录

当前版本已经较完整地体现了过程记录、日报汇总、主管分析这条主线。后续如果继续打通 CRM、增强 AI 能力、完善早晚看板和顾问工作台，这套系统会更接近一个真正可落地的城市内部销售管理工具。
